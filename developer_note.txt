Yes — **that is basically the right algorithm**, but I'd tighten it into something the coding agent can implement without inventing biology.

The biggest correction is that I would not literally “generate (N) nucleation sites” scattered through the cytoplasm. Start with defined MTOCs — initially **one centrosome**, optionally a Golgi/perinuclear nucleation region — and generate *nucleation events through time*. Golgi membranes genuinely can nucleate interphase MTs, but for the very first pass I would actually be happy with centrosome-only if the purpose is debugging the dynamics. ([PubMed Central (PMC)][1])

## Algorithm I would use for V1

### 1. Geometry

Have:

* cell boundary;
* nucleus as an excluded obstacle;
* centrosome just outside the nucleus;
* optionally a Golgi nucleation zone near the centrosome.

At (t=0), nucleate some number of MTs from the centrosome with initial directions sampled approximately uniformly over the accessible solid angle.

**Make them initially straight.** Don't use a persistent random walk. MT persistence lengths measured in vitro are millimetres—orders of magnitude larger than a cell—and substantial intracellular curvature arises from nonthermal forces rather than Brownian bending. ([PubMed Central (PMC)][2])

That alone may dramatically improve the appearance.

---

### 2. Every MT has a dynamic state

Each MT is:

[
S_i(t)\in{\text{growing},\text{shrinking}}.
]

Growing MT:

[
L_i(t+\Delta t)=L_i(t)+v_g\Delta t.
]

Shrinking MT:

[
L_i(t+\Delta t)=L_i(t)-v_s\Delta t.
]

A catastrophe switches:

[
\text{grow}\rightarrow\text{shrink}
]

and a rescue switches:

[
\text{shrink}\rightarrow\text{grow}.
]

If it shrinks all the way back to the MTOC, delete it; the centrosome can subsequently nucleate another MT.

---

# 3. Compute **two different local densities**

This is an important refinement.

The literature actually supports two somewhat different density effects.

### A. Local MT-lattice density around the growing tip

At every growing plus end (x_i), calculate something like

[
\rho_{\rm MT}(x_i)
==================

\sum_j\int_{\mathrm{MT}*j}
K!\left(
\frac{|x_i-r_j(s)|}{\ell*{\rm cat}}
\right)ds.
]

So this is basically **how much existing MT polymer is nearby**.

Use a Gaussian kernel if convenient:

[
K(d)=e^{-d^2/2\ell^2}.
]

Then make catastrophe probability increase with this quantity:

[
f_{\rm cat}(x)
==============

f_{\rm cat,0},
g[\rho_{\rm MT}(x)].
]

The exact (g) should initially be a simple saturating monotonic function rather than something elaborate.

This corresponds most closely to the cellular observation: plus ends entering MT-poor cytoplasm grew persistently, while the same regions began showing catastrophes once MT density increased. The study demonstrated **local-density-dependent catastrophe**, although it did not establish a precise sensing radius. ([PubMed Central (PMC)][3])

So:

[
\boxed{\text{dense region}\Rightarrow\text{higher catastrophe}}
]

becomes the principal **space-filling feedback**.

---

### B. Local density of *growing plus ends*

Separately define

[
\rho_{+}(x_i)
=============

\sum_{j\neq i,;j\text{ growing}}
K\left(\frac{|x_i-x_j|}{\ell_g}\right).
]

Then optionally make growth velocity decrease with (\rho_+):

[
v_g(x)
======

\frac{v_{g,0}}
{1+\alpha_g\rho_+(x)}.
]

There is quantitative experimental support for this: in confined Xenopus cytoplasm, nearby growing MT ends reduced growth velocity, with the strongest relationship at the shortest tested neighborhoods, around **2 µm**, and effects still examined over a few-micron range. The proposed mechanism was local competition for a relatively scarce growth-promoting factor rather than simple tubulin depletion. ([PubMed Central (PMC)][4])

So your intuition:

> inverse density-dependent growth

is legitimate, but it's specifically **growing-tip density → slower plus-end growth**, whereas the catastrophe study is more like **existing MT-rich region → more catastrophe**.

### However…

For the **very first working version**, I would actually switch the growth-density feedback **off**.

Use:

[
v_g=v_{g,0}
]

and only implement density-dependent catastrophe.

Otherwise if the output looks odd we won't know whether catastrophe feedback or growth-rate feedback caused it.

Once the network looks sensible, add the second mechanism.

---

# 4. The nucleus: definitely **not** reduced catastrophe by default

This is the main place I'd change your proposal.

I would treat the nucleus primarily as a **physical obstacle**.

Suppose a growing MT segment would intersect it.

Calculate its incidence angle.

### Grazing encounter

If it approaches approximately tangentially:

[
\theta < \theta_{\rm slide}
]

allow its growing direction to be projected onto the nuclear tangent plane:

[
\mathbf d_{\rm new}
===================

\mathbf d-
(\mathbf d\cdot\mathbf n)\mathbf n.
]

Then continue growth along the surface.

That gives you naturally occurring **MTs curving around the nucleus**.

### Head-on encounter

If it hits more normally:

> stop forward extension → accumulate compressive load → elevated catastrophe probability.

So perhaps:

[
f_{\rm cat,nuc}
===============

m_{\rm stall},f_{\rm cat},
\qquad m_{\rm stall}>1.
]

Growing MTs experimentally become more catastrophe-prone when their plus ends are mechanically stalled against barriers. ([PubMed Central (PMC)][3])

So conceptually:

**glancing collision → deflect/slide**

**head-on collision → stall → likely catastrophe**

rather than

**nuclear contact → stabilization.**

There *is* documented dynein/dynactin-dependent stabilization of MTs around the nuclear envelope, but the strong evidence we discussed is from **late prophase**, which is exactly the wrong state to generalize into our ordinary interphase migration model. ([PubMed Central (PMC)][5])

If later we discover interphase nuclear-envelope capture in our relevant cancer system, add it as an explicit alternative rule.

---

# 5. Cell cortex should work similarly

When the plus end reaches the plasma membrane:

**near-normal contact**

→ stall/compression
→ elevated catastrophe.

**shallow-angle contact**

→ permit cortical sliding.

Actual cellular MTs have been observed contacting the cortex, sliding along it, slowing/stalling and then undergoing catastrophe; the geometry of contact influences the behavior. ([PubMed Central (PMC)][6])

Again: don't tell the MT to “follow the membrane.” Let a contact rule make tangential continuation mechanically possible.

---

# 6. Run all MTs simultaneously

This is another thing I'd make explicit to the coding agent.

Don't:

> generate MT 1 to completion → generate MT 2 → generate MT 3 …

because the density feedback then depends arbitrarily on generation order.

Instead:

```text
initialize MTOC
nucleate initial MT population

for each timestep:

    possibly nucleate new MTs

    calculate current local MT density field

    calculate current growing-plus-end density field

    for every MT simultaneously:

        if growing:
            calculate proposed extension

            if extension hits nucleus:
                apply nucleus contact rule

            if extension hits cortex:
                apply cortex contact rule

            otherwise:
                extend straight ahead

            calculate local catastrophe rate
            stochastic catastrophe yes/no

        if shrinking:
            retract plus end along existing MT path
            stochastic rescue yes/no

            if length reaches zero:
                remove MT

    update density fields
```

Run until basic network statistics reach stationarity and then take snapshots.

## 7. What should make the network space filling?

This is the part I now like.

Suppose one sector happens by chance to contain very few MTs:

[
\rho_{\rm MT}\downarrow
]

so MTs entering it have:

[
f_{\rm cat}\downarrow.
]

They therefore tend to **keep growing farther into that region**.

Eventually:

[
\rho_{\rm MT}\uparrow
]

and consequently:

[
f_{\rm cat}\uparrow.
]

Growth into that sector stops being exceptionally persistent.

Meanwhile overcrowded sectors destroy growing extensions more readily.

You therefore get:

[
\boxed{
\text{local negative feedback}
\rightarrow
\text{approximately space-filling global network}
}
]

without ever programming:

> “find an empty part of the cell.”

That's exactly what I think we want to test.

# 8. One thing I would absolutely show the coding agent

The desired network should initially look roughly like:

```text
                \    |   /
                 \   |  /
        -----------\ | /---------
                     ● centrosome
                 ___/ \___
               /           \
              /   nucleus    \
             /               \
              \             /
               \___________/
             /  /       \   \
           /   /         \    \
         /    /           \     \
```

Not:

```text
~~~~~\_/~~\/~~~~\
 /~~~~\/\~~~~~~
~~~~\/~~~~\/~~~~~
```

The **default MT should be long and nearly straight**.

Curvature should be visually concentrated where there is a reason for it:

* grazing nucleus;
* grazing cortex;
* explicit mechanical force;
* perhaps later interactions with actomyosin/other structures.

If the coding agent's original implementation looked like a plate of spaghetti, I suspect the random-direction update/persistence rule was a major culprit.

---

## So the minimal version I'd build first

I would genuinely start with only:

[
\boxed{
\begin{aligned}
&\text{centrosomal nucleation}\
&+\text{straight plus-end growth}\
&+\text{constant }v_g,v_s\
&+\text{density-dependent catastrophe}\
&+\text{constant rescue}\
&+\text{nuclear/cortical collision rules}
\end{aligned}}
]

Get that looking sane.

Then in order add:

1. **plus-end-density-dependent growth speed** over a ~2 µm kernel; ([PubMed Central (PMC)][4])
2. Golgi nucleation;
3. externally generated bending/curvature;
4. track transport;
5. finally dynamic transport on a network that itself turns over.

That progression should make it much easier to tell whether an ugly result is a bug, an unfortunate parameter choice, or an actual emergent property of the model.
