# migration1d

> **Deprecated for WP1 model development.** This package is retained only so
> earlier campaigns remain reproducible. New Jilkine and De Belly 1D work uses
> `../polarity1d/`. Do not add new models, protocols, or screens here.

`migration1d` was developed as an installable library for reaction-diffusion chemistry on a
moving finite interval with endpoint Kelvin-Voigt mechanics. Chemistry,
mechanics, endpoint force mappings, campaigns, and output paths are separate.

Experiments are organized by chemical complexity rather than publication:

- `single_species`: one active/inactive polarity species;
- `three_species`: interacting Cdc42, Rac, and Rho polarity species.

Both branches use the same `parameter_mapping`, `calibration`, and `testing`
stages. Published-model names identify parameterization provenance inside a
campaign; they do not define the directory layout. See `configs/README.md` for
the classification and the shared panel definitions.

## Optional tension feedback

`MigrationModel.tension_feedback` accepts either `GlobalTensionFeedback` or
`SpatialTensionFeedback`. Global feedback uses only the positive elastic spring
force, so compression and dashpot force do not alter Rac-equivalent
deactivation. Spatial feedback integrates a separate no-flux material field
`theta = T - T0`, generated by positive local protrusive activity, relaxed on
`relaxation_time`, and propagated with `diffusivity`. Its communication length
is available as `feedback.characteristic_length = sqrt(D_T * tau_T)`.

The single-species model interprets its sole active GTPase as the operational
Rac/protrusion variable without changing its nominal species name. Holmes and
Eroume target their explicit Rac active/inactive pools. All couplings transfer
active material to the appropriate inactive pool and preserve the relevant
GTPase total.

## Run campaigns

Use the repository's existing Conda environment:

```bash
conda run -n scaling_sandbox python migration1d/run.py \
  migration1d/configs --list
```

Run one short campaign locally:

```bash
conda run -n scaling_sandbox python migration1d/run.py \
  migration1d/configs --select single-testing-smoke --local
```

Submit the enabled config directory to SLURM:

```bash
conda run -n scaling_sandbox python migration1d/run.py \
  migration1d/configs --submit
```

The runner normally submits one ordinary job per selected config. A config with
`batch.array_tasks` instead submits the declared unthrottled SLURM array. If it
also defines `batch.merge_arguments`, the runner submits a small `afterok`
merge/report job that runs only after every array task succeeds. Resource shapes
live beside the scientific campaign selection in each JSON file; no array `%`
concurrency throttle is added implicitly.

The runner recursively discovers campaign JSON files while ignoring the
non-runnable shared definitions under `configs/_standards/`. Each campaign
declares its chemistry class, workflow stage, protocol, parameterization
provenance, package module, output directory, optional arguments, and scheduler
resources. Standardized analyses live under `src/migration1d/single_species/`
and `src/migration1d/three_species/`; older three-species campaigns remain under
`src/migration1d/campaigns/`. There are no independent
`scripts/run_*.py` entry points.

## Develop and test

An editable install is optional because the runner and pytest configuration
add `src/` explicitly:

```bash
conda run -n scaling_sandbox pytest migration1d/tests
```

Outputs under `results/` are ignored generated artifacts, not package source.
New outputs follow `results/<chemistry_class>/<stage>/<experiment>/`.

Each completed single-species analysis writes PNG figures, CSV/JSON data, and
`figure_manifest.json`. After any subset of analyses has completed, assemble
all available sections into the single HTML report with:

```bash
conda run -n scaling_sandbox python migration1d/report.py
```

This writes the only HTML report,
`migration1d/results/single_species/report.html`. Missing analyses are omitted,
so the report never silently presents stale placeholders.
